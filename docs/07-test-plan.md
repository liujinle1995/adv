# 测试用例与验收标准

> 每条用例必须记录：设备型号 / ROM / API / 引擎版本 / 实际结果 / 日志片段。
> **禁止用"应该""理论上"作为结论。**

## 1. 验收标准（对应需求第七节，逐条给出验证方法）

| # | 验收项 | 验证方法 | 判定 |
|---|---|---|---|
| AC1 | 导入后准确显示包名/版本/签名 | 与 `aapt2 dump badging` + `apksigner verify --print-certs` 输出的 SHA-256 逐字段比对 | 完全一致 |
| AC2 | 同包名不同签名不覆盖宿主原应用 | 操作前后执行 `adb shell dumpsys package <pkg> \| findstr versionCode`、`pm path <pkg>`、对比签名摘要 | 三项均未变化 |
| AC3 | 引擎支持范围内可独立安装/启动/停止/重启 | TC-10 ~ TC-16 | 全部通过，且状态与实际一致 |
| AC4 | 目标应用能登录、联网、保存数据 | TC-20 ~ TC-24 | 通过（登录失败若归因于签名绑定，需书面记录为"引擎外限制"） |
| AC5 | 删除实例不影响宿主数据 | TC-30 ~ TC-32 | 宿主数据 hash 不变 |
| AC6 | 记录安装/启动失败、崩溃、ANR | TC-40 ~ TC-44 | 每类都能在诊断页看到 |
| AC7 | 异常退出与重启后恢复合理状态 | TC-50 ~ TC-54 | 无"假运行中" |
| AC8 | 不夸大隔离能力 | 文案审查 + 设置页能力表 | 每个 `UNSUPPORTED/PARTIAL` 在 UI 可见 |

## 2. APK 导入与解析

| ID | 用例 | 步骤 | 期望 |
|---|---|---|---|
| TC-01 | 正常 APK 导入 | SAF 选择普通 APK | 指标全部正确，SHA-256 与 `certutil`/`sha256sum` 一致 |
| TC-02 | 大文件导入 | 选 200MB+ APK | 进度可见，内存不 OOM（用 Android Studio Profiler 观察） |
| TC-03 | 非 APK 文件 | 选 jpg 改名为 .apk | `INSTALL_FAILED(不是合法 APK)`，不崩溃 |
| TC-04 | 损坏 APK | 截断文件 | 明确报错，不建实例 |
| TC-05 | 同文件重复导入 | 连续导入同一个 APK 两次 | 复用记录，存储不翻倍 |
| TC-06 | 同版本不同内容 | 同 versionCode 但重签名的 APK | 标记"同版本不同内容"，要求用户确认 |
| TC-07 | split APK（仅 base） | 导入只有 base 的分包 | 标记 `isSplitApk`，提示"可能缺少 ABI/资源分包" |
| TC-08 | 无 launcher activity | 导入无入口的 APK | 显示"无可启动入口"，启动按钮置灰 |
| TC-09 | 签名读取 | 多签名 APK | `signerSha256` 列出全部证书 |

## 3. 实例生命周期

| ID | 用例 | 期望 |
|---|---|---|
| TC-10 | 首次安装 | 状态 `INSTALLING→INSTALLED`，写入 `virtualUserId` |
| TC-11 | 启动 | `STARTING→RUNNING`，且 `RUNNING` 有进程证据 |
| TC-12 | 停止 | `RUNNING→STOPPED`，进程确实消失 |
| TC-13 | 重启实例 | 数据保留，会话按目标 App 自身逻辑保持 |
| TC-14 | 同签名升级 | `SAME_SIGNATURE_UPDATE`，数据保留 |
| TC-15 | 不同签名覆盖 | 拒绝自动覆盖，弹二次确认，选"新建实例"可成功（若引擎支持） |
| TC-16 | 二次确认取消 | 数据库无任何变化 |
| TC-17 | 重复点击启动 | 不产生多个 client 进程（按钮防抖 + 引擎串行化） |
| TC-18 | 未安装就启动 | 明确报错，状态不变 |

## 4. 数据隔离

| ID | 用例 | 期望 |
|---|---|---|
| TC-20 | 两实例数据独立 | A 实例写入的数据在 B 实例不可见 |
| TC-21 | 与宿主数据隔离 | 沙箱内 App 无法读取宿主 `files/`（用恶意 Probe 尝试路径穿越） |
| TC-22 | 清缓存 | 只删 `cache/`，登录态保留 |
| TC-23 | 清除数据 | 数据根被重建，App 回到首次启动 |
| TC-24 | 删除实例 | 数据根 + 包表 + DB 行全部清除，`files/apks/` 中的 APK 库不受影响 |
| TC-25 | 备份/恢复 | 同包名+同签名+同引擎可恢复；不同则拒绝 |
| TC-26 | 孤儿目录 | 人为造一个无实例行的目录 | 出现在"存储清理"里且需确认才删 |

## 7. 异常与恢复

| ID | 用例 | 期望 |
|---|---|---|
| TC-50 | 安装中强杀宿主 | 重启后状态为 `UNKNOWN_INTERRUPTED`，可重试 |
| TC-51 | 运行中强杀宿主 | 重启后对账为已停止/崩溃，不显示运行中 |

| TC-54 | 引擎自检失败 | 全实例标 `ENGINE_INCOMPATIBLE`，提供"重装实例（保留 APK）" |
| TC-55 | 数据库升级 | 迁移后数据完整，无实例丢 `data_root` 引用 |
