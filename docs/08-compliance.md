# 开源许可证与发布合规清单

> 本文是工程侧自查清单，**不构成法律意见**。凡标注"需法务确认"的条目，必须由法务出书面结论后才能发布。

## 1. 引擎选型的许可证风险（这是本项目最大的合规雷区）

| 引擎 | 许可证事实（本次核实） | 可商用 | 义务 / 风险 |
|---|---|---|---|
| **VirtualApp（asLody）** | 仓库**无 `LICENSE` 文件**；README 明确要求购买商业授权，归属"山东盒一网络科技有限公司"，并声明未授权使用将报警（侵犯著作权罪）或起诉 | **否，除非付费授权** | 即使只用于"内部测试"，README 也把"内部使用"列为需授权情形。**未签约前不得把代码引入仓库、不得反编译商业版、不得用于任何对外分发** |
| **BlackBox 2.1.0** | `LICENSE` = Apache-2.0（"Copyright 2022 BlackBox"）；默认分支源码已被作者清空，代码只在 tag 中 | **是** | ①保留 `LICENSE` 与版权声明；②修改过的文件需注明"已修改"；③若有 `NOTICE` 需随分发保留；④Apache-2.0 **不授予商标权**，不得使用 "BlackBox" 名称/图标做产品标识；⑤代码血缘含 VirtualApp —— **需法务确认上游"无许可证"是否会对下游 Apache-2.0 授权链造成瑕疵**（BlackBox 作者有权就其修改部分授权，但原始 VirtualApp 部分的权利来源存在争议） |
| **NewBlackbox / 各类 fork** | Apache-2.0（保留 "Copyright 2022 BlackBox"） | 形式上可以 | 但维护质量不可控，且血缘更复杂；**不建议引入** |
| **DroidPlugin** | **LGPL-3.0** | 有条件 | LGPL 要求：动态链接使用、允许用户替换该库（提供修改后的库源码）、不得静态链接进闭源产物。Android 上"动态链接"边界如何界定**需法务确认**；且开源代码老旧，无实用价值 |
| **VirtualAPK** | Apache-2.0 | 是 | Apache-2.0 义务；但功能不匹配需求 |
| **twoyi** | **MPL-2.0** | 是 | 文件级 copyleft：修改过的 MPL 文件需开源；但其内部 ROM 未开源、需从 Release 提取 `rootfs.7z` → **再分发该 ROM 的合法性需确认** |
| **AVF / Microdroid** | AOSP（Apache-2.0 + 部分 BSD） | 是 | 但技术上不满足需求 |

### 1.1 关于"社区 fork 标了 GPL-3.0"的特别提醒

部分 VirtualApp fork 在 GitHub 上标注 `GPL-3.0`，而上游仓库**根本没有 LICENSE 文件**。这类标注**不能当作有效授权**：
- 若上游未授权，fork 方无权单方面以 GPL 授权；
- 若误用 GPL-3.0 代码进闭源产品，会触发**整仓开源义务**。

**结论：不要把任何来源不明的 VirtualApp fork 代码合入本仓库。** 需要引入时，走"向原厂付费授权"这一条唯一路径。

## 2. 自身代码的许可证策略

| 项 | 建议 |
|---|---|
| 自有代码 | 闭源商业 / 或 Apache-2.0 开源（若想建生态）。**一旦选了 Apache-2.0 就不能回头闭源**，先定策略再写代码 |
| 仓库内第三方代码 | 单独放 `third_party/`，每个目录保留原始 `LICENSE` + 记录来源 URL 与 commit/tag |
| SBOM | 用 CycloneDX Gradle 插件生成，随每个 Release 归档 |
| 版权头 | 引入的第三方源码文件**不得**改成自己的版权头 |

## 4. 应用商店与分发合规

| 项 | 状态 | 说明 |
|---|---|---|
| Google Play「设备与网络滥用」「干扰其他应用」政策 | **需核实** | 运行第三方 APK 的沙箱类应用在 Play 上架有额外审查，部分同类产品被下架。上架前必须逐条比对当期政策原文 |
| Google Play 目标 API 要求 | 需遵守 | 宿主 App 自身的 `targetSdk` 需满足当年要求 |
| 国内应用商店 | 需核实 | 通常需要：软件著作权登记、App 备案（工信部）、隐私政策、权限说明、内容合规 |
| 内置 APK 分发 | 需核实 | **不得**把第三方商业 App 的 APK 打包进发行包（侵权）。只能由用户从本机导入 |
| 名称/图标 | 必须 | 不得使用 "BlackBox"/"VirtualApp" 商标或图标；不得宣称"官方" |
| 免责声明 | 必须 | 明确：本应用仅提供运行环境，不对第三方应用内容与账号行为负责；使用风险自负 |

## 5. 隐私与数据合规

| 要求 | 落地 |
|---|---|
| 最小必要 | 只读 APK 元数据；不读取通讯录/短信/位置 |
| 不收集账号凭据 | **架构上不接触**目标 App 的账号密码；日志脱敏过滤 `token/password/cookie/Authorization` |
| 权限清单 | 设置页与商店页逐条列出并说明用途 |
| 日志本地化 | 日志只存本机，默认不上传；导出需用户手动操作 |
| 诊断包脱敏 | 导出前跑 `LogRedactor`，并提示"请自行检查后再发送" |
| 删除权 | 提供"一键清除所有数据"，删除后不可恢复 |
| 儿童/敏感场景 | 不面向儿童；不做金融类 App 的"多开"宣传（易被判定为绕过风控） |

## 6. 发布前合规检查单（Release Checklist）

- [ ] 引擎授权文件（合同/发票/授权范围）已归档，且覆盖"对外分发"
- [ ] 仓库内无来源不明的 VirtualApp / GPL 代码（`git log` + 代码扫描确认）
- [ ] `third_party/` 下每个组件都有 LICENSE 与来源记录
- [ ] Apache-2.0 组件的 `LICENSE`/`NOTICE` 出现在 App 的"开源许可"页面
- [ ] 未使用任何第三方商标作为产品名/图标
- [ ] SBOM 已生成并归档
- [ ] 隐私政策、用户协议、免责声明已上线且与实际行为一致
- [ ] 商店页面文案不含"虚拟机/独立内核/绝对隔离/防封号"等表述
- [ ] 权限清单与实际 `AndroidManifest` 一致（多一个都算违规）
- [ ] 目标 App 的 APK **未**被打包进发行包
- [ ] 法务对 §1 的"血缘瑕疵"与 §4 的商店政策给出书面结论
